## Published-service read-only observation

The observation below was performed on 2026-07-31 without authentication. It is evidence of the service state at that time, not a deployment approval.

| Request | HTTP result | Observation |
|---|---:|---|
| `GET /` | 404 | Generic HTML 404; no stack trace or server configuration exposed |
| `GET /api/v1/health/` | 200 | Stable JSON health envelope |
| `GET /api/v1/health/live/` | 200 | `code=LIVE`, process liveness healthy |
| `GET /api/v1/health/ready/` | 503 | `code=SERVICE_NOT_READY` |
| `GET /api/v1/health/startup/` | 503 | `code=STARTUP_NOT_READY` |

HTTPS was in use and the sampled responses carried `X-Request-Id`, `X-Content-Type-Options`, CSP, frame, referrer, permissions, and cross-origin isolation headers. The failing readiness and startup endpoints are release blockers until investigated on Coolify with dependency-safe diagnostics.

## P0 identified before remediation

`StandardReadOnlyModelViewSet` inherited `StandardResponseMixin`, which supplied `create`, `update`, and `destroy`. DRF router method discovery can therefore expose write verbs for subclasses nominally intended as read-only. This is treated as P0 and is remediated first with route-level contract tests.
