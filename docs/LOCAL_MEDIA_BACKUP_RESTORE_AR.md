# النسخ الاحتياطي والاستعادة لملفات media المحلية

## ما الذي يجب نسخه

PostgreSQL يحتوي مفاتيح الملفات وبياناتها الوصفية فقط، وليس محتوى الملفات. لذلك
يلزم نسخ قاعدة PostgreSQL وVolume `media` معًا وبنافذة اتساق واحدة. نسخة قاعدة
البيانات وحدها لا تستعيد الوثائق أو المرفقات، ونسخة الـVolume وحدها لا تعيد
الملكية أو التذاكر أو سجلات التدقيق.

## سياسة مقترحة

- نسخة يومية مشفرة خارج خادم Coolify، مع retention يومي 35 يومًا وأسبوعي 12
  أسبوعًا وشهري 12 شهرًا حسب سياسة الخصوصية المعتمدة.
- نسخة قبل كل Release، مع تسجيل SHA للصورة، وقت النسخة، وعدد الملفات وحجمها.
- اختبار استعادة معزول شهريًا وعلى Staging قبل ترقية إنتاجية حساسة.
- أوقف الكتابة مؤقتًا أو استخدم snapshot متسقًا عند أخذ قاعدة البيانات والـVolume
  لكي لا تشير قاعدة البيانات إلى ملف لم يدخل النسخة أو العكس.

## تحديد الـVolume

لا تفترض script اسمًا مركبًا؛ اسم Docker الحقيقي قد يسبقه اسم مشروع Coolify.
حدده من التطبيق أو من المضيف:

```sh
docker volume ls
docker volume inspect <actual-volume-name>
```

لا تستخدم `docker system prune --volumes`، ولا تحذف Volume عند نشر صورة جديدة.

## إنشاء archive

يتطلب السكربت اسم Volume صريحًا ومجلداً موجودًا وآمنًا للخرج؛ لا يحذف المصدر:

```sh
sh scripts/backup_local_media.sh <actual-volume-name> /secure/backups
```

للمراجعة من دون كتابة archive:

```sh
sh scripts/backup_local_media.sh <actual-volume-name> /secure/backups --dry-run
```

يُنصح بتشفير archive بعد إنشائه باستخدام آلية مؤسسية منفصلة وإبقاء مفتاح التشفير
خارج Coolify. تحفظ معه checksum في المسار نفسه.

## الاستعادة المعزولة

1. أنشئ بيئة Staging منفصلة وVolume جديدًا، ولا تستعد فوق الإنتاج.
2. تحقق من checksum ومحتويات archive:

   ```sh
   sh scripts/verify_local_media_backup.sh /secure/backups/<archive>.tar.gz \
     /secure/backups/<archive>.tar.gz.sha256
   ```

3. استعد PostgreSQL إلى قاعدة Staging المتوافقة مع إصدار التطبيق.
4. فك archive إلى Volume الوجهة باستخدام حاوية صيانة موثقة، مع المحافظة على
   UID/GID `10001:10001` عند الحاجة.
5. شغّل التطبيق، ثم نفذ `storage_status --write-test` وSmoke tests بعينات
   اصطناعية فقط.
6. قارن عدد الملفات والأحجام وchecksums مع manifest النسخة، ثم تحقق من أن
   مراجع الملفات في قاعدة البيانات قابلة للقراءة عبر الـAPI المحمي.

سجّل زمن النسخ والاستعادة لتحديد RPO/RTO الفعليين. هذا الدليل لا يمثل دليل تنفيذ
استعادة حتى يُسجل تمرين ناجح.
