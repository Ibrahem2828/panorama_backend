# Panorama Backend v2 — التحويل إلى مرشح إنتاج احترافي

## الحالة
هذه النسخة هي **Production Candidate / Reference Implementation** وليست ادعاءً بأن الإنتاج أصبح مضمونًا بنسبة 100% دون تشغيل الاختبارات وقاعدة البيانات ومزودي البريد والتخزين والإشعارات في بيئة Staging ثم Production.

## القرارات المعمارية الحاسمة

1. الباك إند هو مصدر الحقيقة للصلاحيات والتسعير وحالات الإجراءات.
2. لا يُعاد أي رابط تخزين خام للبطاقات أو الملفات أو مرفقات الدعم أو مرفقات الشات.
3. كل معاينة حساسة تعتمد تذكرة قصيرة العمر، محدودة الاستخدام، وغير قابلة للتخمين.
4. رابط واتساب مشفر في قاعدة البيانات ولا يظهر داخل JSON؛ يحصل العضو المصرح له على رابط فتح مؤقت لمرة واحدة.
5. التوثيق ينتقل إلى `pending` فقط عند إنشاء `VerificationRequest` فعلي.
6. السعر النهائي للطباعة يُحسب داخل الباك من قواعد فعالة ويُحفظ Snapshot كامل داخل الطلب.
7. OTP يُخزن Hash فقط، مع تباطؤ، مدة صلاحية، حد محاولات، قفل، وإبطال الرموز السابقة.
8. جلسات JWT تستخدم Refresh Rotation وBlacklist، وتُبطل الجلسات السابقة بعد تغيير كلمة المرور.
9. جميع الأدوار الإدارية تعمل عبر Capabilities مع Overrides صريحة قابلة للتدقيق والانتهاء.
10. التقييمات والاقتراحات جزء من المنصة وليس نموذجًا خارجيًا منفصلًا.

## الوحدات الجديدة أو المعاد بناؤها

- RBAC احترافي: أدوار، Capabilities، Allow/Deny overrides، تاريخ انتهاء، وتدقيق.
- Email OTP باستخدام SMTP وحساب Panorama الرسمي عبر متغيرات البيئة.
- Protected Asset Delivery للملفات والبطاقات والطباعة والدعم والشات.
- Encrypted External Channels لإخفاء رابط واتساب من التخزين والاستجابات.
- Dynamic Printing Pricing Engine مع قواعد أسعار وتكاليف تجليد ومواقع استلام.
- Feedback & Product Discovery: تقييم 1–5، أخطاء، شكاوى، اقتراحات، تصويت، سياسات إظهار، وتحليلات.
- Hardened WebSocket Chat: حدود أحجام، Rate Limits، أخطاء عامة، صلاحيات، ومرفقات محمية.
- Push Notification Adapter + Celery background tasks.
- Data Retention command للـOTP والتذاكر المؤقتة وصور البطاقات القديمة.
- Runtime-only container + separate release command + non-root Docker image.
- CI Quality Gate للاختبارات، schema drift، OpenAPI، security scan، dependency audit.

## تدفق الطالب المرجعي

1. إنشاء حساب طالب بالبريد والهاتف وكلمة مرور قوية.
2. إرسال OTP للبريد أو مزود الهاتف المفعّل.
3. منع تسجيل الدخول الكامل قبل إثبات إحدى الهويتين.
4. إكمال الملف الأكاديمي.
5. رفع البطاقة عبر `VerificationRequest` فقط.
6. انتقال الحالة إلى `pending` داخل Transaction واحدة.
7. مراجعة إدارية مع رفض المراجعة الذاتية وإلزام سبب الرفض أو طلب التحديث.
8. قبول التوثيق وتحديث `StudentProfile` وإرسال إشعار.
9. الوصول إلى المواد والغروبات والملفات حسب الأهلية من الباك.

## تدفق التقييم والتحسين المستمر

الفرونت لا يعرض نافذة تقييم عشوائية بعد كل ضغطة. بعد اكتمال إجراء ناجح يرسل:

- `context`: المجال، مثل `printing` أو `file`.
- `action_key`: الحدث، مثل `printing.order.delivered`.
- `app_version` و`build_number` والمنصة.

ثم يطلب `/api/v1/feedback/prompt/`. يقرر الباك الإظهار بناءً على:

- سياسة مفعّلة من الداشبورد.
- Cooldown.
- Sample percentage.
- الحد الأدنى لإصدار التطبيق.
- تاريخ إظهار/إرسال المستخدم السابق.

عند الإرسال يمكن للمستخدم تقديم:

- تقييم من 1 إلى 5.
- تعليق.
- اقتراح.
- بلاغ خطأ.
- شكوى أو إشادة.

التقييم لن يتكرر لنفس المستخدم والإجراء والعنصر وإصدار التطبيق؛ بل يُحدث السجل السابق. الاقتراح لا يصبح عامًا إلا بعد مراجعته ووضعه في `planned` أو `in_progress` أو `resolved`.

## رابط واتساب

لا يمكن تقنيًا إخفاء الوجهة النهائية عن مستخدم مخول بعد أن يفتحها في متصفحه، لأن المتصفح يحتاج معرفة الرابط للانتقال. الحماية الصحيحة المطبقة هي:

- تشفير الرابط داخل قاعدة البيانات.
- عدم إظهاره في API أو الجداول العامة.
- إظهار `has_whatsapp_channel` فقط.
- التحقق من عضوية المستخدم.
- إصدار تذكرة عشوائية قصيرة العمر ولمرة واحدة.
- استهلاك التذكرة داخل Transaction.
- منع التخزين المؤقت وإرسال `Referrer-Policy: no-referrer`.
- تسجيل الإصدار والفتح في Audit Log دون حفظ الرابط الخام.

## بريد OTP

القيمة الافتراضية:

- `SUPPORT_EMAIL=panoramacompany31@gmail.com`
- `EMAIL_HOST_USER=panoramacompany31@gmail.com`
- `EMAIL_HOST=smtp.gmail.com`
- `EMAIL_PORT=587`
- `EMAIL_USE_TLS=True`

لا توضع كلمة مرور Gmail في Git أو الملفات. يجب تفعيل التحقق بخطوتين وإنشاء **App Password** وحفظه في Secret Manager باسم `EMAIL_HOST_PASSWORD`.

- جميع اختبارات Pytest.
- Contract tests مع الموبايل والداشبورد.
- اختبار اختراق مستقل للصلاحيات وIDOR وOTP والملفات.
- Load test للـREST وWebSocket والطباعة.
- اختبار استعادة Backup فعلي.
- اختبار إرسال Gmail SMTP وPush Provider في Staging.
